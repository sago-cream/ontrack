資料來源與整合 / Data & integration

This is an isolated design and data-policy prototype. Run bun prototypes/train-service/build.ts, then serve .review/train-service over HTTP. The draft also includes timetable flag mapping and matching web/native iOS screens. Route advisories and stale-report expiry remain prototype policies.

Official TDX Rail v3 schema · verified 2026-11-15

  • DailyTrainTimetable/Today or DailyTrainTimetable/TrainDate/{date}: train SuspendedFlag is 0 normal, 1 cancelled, 2 partial; stop SuspendedFlag is 0 open, 1 suspended. The current Worker already fetches both nested objects.
  • Alert returns Alerts with affected trains, routes, lines, stops, sections, validity times and source timestamps. A matching alert is advisory; Status=2 does not confirm cancellation. Alert direction uses south/north semantics; timetable direction uses clockwise/counterclockwise semantics.
  • News returns Newses with descriptions and official links. Retain for human inspection; a keyword such as 停駛 cannot establish a specific train or date is cancelled.

The prototype hides trains with full cancellation, suspended endpoints, unresolved partial service, stale reports or missing flags, and excludes them from recommendation and sharing. Delay data never establishes service availability. Broad alerts ask the user to verify rather than removing trains.

Production follow-up: validate authenticated payload freshness and refresh budgets; map service availability separately from delay status; key by Taipei service date + train number + journey; add timestamped service metadata; invalidate derived OD snapshots after a refresh. Refresh today’s flags and alerts using a shared, budgeted snapshot with conditional requests. The 120-second freshness threshold here is a proposal, not a TDX guarantee. Do not retimestamp unchanged old content without validation.

Apply eligibility consistently to web/Android, iOS selection, share summaries and widget projection. Persisted selected trains must be reconciled when availability changes. Test all-cancelled and restore transitions, dates, unknown fields, interior sections, missing times, stale cache and failed feeds before shipping.

Probe with node --env-file=/private/path.env prototypes/train-service/fetch-tdx.mjs YYYY-MM-DD. Uses existing TDX credential names and paginates the responses. An unauthenticated live request returned HTTP 401; fixture scenarios demonstrate schema behavior, not actual cancelled trains.
