## Features

- Real-time train schedules from [TDX](https://tdx.transportdata.tw/)
- Detect your current station automatically
- Predict routes based on your riding habits
- Show real-time departures and delay information as soon as you open the app
- Quick destination and arrival time sharing

## Repository Layout

- `apps/ios`: iOS app, Xcode project, and Xcode build resources
- `apps/android`: Capacitor Android app and Gradle build resources
- `apps/web`: web app and public site assets
- `apps/worker`: Cloudflare Worker deployment wrapper
- `assets/screenshots`: App Store screenshots generated by `bun run ios:screenshots`

## Official App

The official OnTrack app and website are published by Hsi at
[ontrack.hsichen.dev](https://ontrack.hsichen.dev). Forks should use their own
app name, bundle identifier, icons, screenshots, support links, privacy policy,
and deployment endpoints.

## Install

Download OnTrack for iPhone and iPad from the
[App Store](https://apps.apple.com/tw/app/ontrack/id6784708806).

Use the web app at [ontrack.hsichen.dev/app](https://ontrack.hsichen.dev/app),
or build the native Android app from this repository.

### Android (Chrome)

1. Open the app in Chrome on [ontrack.hsichen.dev/app](https://ontrack.hsichen.dev/app)
2. Tap the ⋮ menu (top right)
3. Select "Add to Home screen" or "Install app"

## Development

Install dependencies:

```sh
bun install
```

Run the web app:

```sh
bun run dev
```

To point the development web app at another backend, set
`ONTRACK_API_ORIGIN`:

```sh
ONTRACK_API_ORIGIN=https://example.com bun run dev
```

Build the web app and Worker:

```sh
bun run build
```

Deploy a development Worker after filling the D1 placeholder in
`apps/worker/wrangler.jsonc`:

```sh
bun run deploy:dev:dry-run
bun run deploy:dev
```

Run lint:

```sh
bun run lint
```

Run the iOS app on a connected device:

```sh
bun run ios
```

Build, open, install, and launch the iOS app in an available simulator:

```sh
bun run ios:simulator
```

To compile the iOS app without opening a simulator, run `bun run ios:build`.

To point iOS scripts at another backend, set `IOS_API_ORIGIN`:

```sh
IOS_API_ORIGIN=https://example.com bun run ios
```

Build, install, and launch the Android app on a connected device or emulator:

```sh
bun run android
```

Run Android lint and JVM tests with `bun run android:check`, or run device
instrumentation with `bun run android:test:device`. See
[`docs/android-release.md`](./docs/android-release.md) for signed App Bundles,
Play Store metadata, screenshots, and publishing.

## Self-Hosting

OnTrack reads public railway data from TDX through a Cloudflare Worker. The
tracked `apps/worker/wrangler.jsonc` is a development-safe config with
placeholder D1 values. To host a fork, use your own infrastructure and
credentials.

1. Create your own Cloudflare D1 database.
2. Copy the production config example:

```sh
cp apps/worker/wrangler.production.example.jsonc apps/worker/wrangler.production.jsonc
```

3. Fill in the Cloudflare `account_id`, production route, and D1 `database_id`
   in the ignored `apps/worker/wrangler.production.jsonc`.
4. Set `CORS_ALLOWED_ORIGINS` in the production config to your web origin.
5. Set Worker secrets as needed:

```sh
wrangler secret put TDX_CLIENT_ID --config apps/worker/wrangler.production.jsonc
wrangler secret put TDX_CLIENT_SECRET --config apps/worker/wrangler.production.jsonc
wrangler secret put REFRESH_SECRET --config apps/worker/wrangler.production.jsonc
```

6. Validate the private config and run a production dry-run:

```sh
bun run deploy:prod:check
bun run deploy:prod:dry-run
```

7. Deploy:

```sh
bun run deploy
```

Official maintainers also use the ignored production config, so production
deploys do not require editing the tracked public config. Never put Cloudflare
account, zone, route, or D1 identifiers in tracked files; keep credentials in
Wrangler secrets/provider storage. The deploy command refuses unresolved
template placeholders.

TDX credentials are optional for development because the Worker falls back to
Visitor Mode when they are not configured.

For native distribution, use your own Apple or Google developer account, app
identifier, store listing, support URL, privacy policy, and signing credentials.
